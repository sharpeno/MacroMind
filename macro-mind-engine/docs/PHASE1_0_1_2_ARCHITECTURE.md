# Phase 1.0–1.2 architecture

The authoritative frozen contract is `../golden_sample_test/core_ontology/v0.3/`
relative to the engine root. `contracts/v0_3` contains only a reference README.
Manifest → object definitions → boundaries → principles → canonical Markdown →
change policy → projection → source mapping is the authority order. Historical
Golden/MA.1 files inform auxiliary representation only, never Core definitions.

The engineering progression is Contract → Schema → Registry. The code dependency
direction is deliberately different: contract metadata is independent; Registry
YAML generates Python enums; schemas consume generated enums. Registry integrity
checks compare generated bytes with YAML without importing schemas, avoiding a
circular dependency. CLI combines these modules and exports only after integrity
checks pass. Schema changes do not imply an ontology version change.

The loader reads all ten artifacts as data, verifies nine output SHA-256 records,
exact Core/Boundary/Principle sets, freeze/readiness flags and semantic hash using
the unchanged Freeze Commit algorithm. Projection object/Boundary/Principle and
policy content must agree with the authoritative files. Manifest paths are
historical provenance; allowlisted basenames resolve under the caller's root.
Manifest has no self-hash or signature; a coherently replaced entire contract is
outside self-contained hash validation. The run's independent input snapshot and
freeze commit provenance record the original bytes.

Pydantic uses extra=forbid. Required semantic fields may explicitly contain null
or unknown where evidence can be absent. Missing a required key fails. Enum unknown
is a controlled value; nested unknown is an explicit object. No missing semantic
value is guessed. Metadata defaults, field requiredness and storage representation
are implementation choices documented in SCHEMA_MAPPING.md. Free prose such as
modal_strength and assessment_kind is intentionally not an invented closed taxonomy.

All 14 Core and 12 non-Core models export Draft 2020-12 JSON Schema. Nested value
structures appear under `$defs`; they do not create additional Core types. Stable
sort order, UTF-8, LF and no timestamps make generated artifacts reproducible.
The schema manifest hashes each exported object schema. CLI run metadata lives on
stderr as structured JSON, outside deterministic semantic outputs.

Only contract integrity, structural Pydantic checks and registry integrity exist.
Reference resolution, truth propagation guards, forecast admission, process evidence
sufficiency, argument validity, chronological recurrence and Skill promotion remain
Phase 1.3 or later. No Golden migration or production import is implemented.

Tests mutate temporary copies only. `phase1/input_hashes.json` covers the existing
golden_sample_test tree; session teardown and final Gate compare every protected
file and file membership. Historical debt records remain immutable. D02, D07, D16
and D18 receive only partial-progress entries in a new Phase 1 overlay.
