# 分析师框架独立执行说明

本说明可在新会话中使用，目标为9527分析框架的忠实还原或迁移。它是研究提示包，不是已部署运行器或已验证Skill。输入组装者先按下述规则裁剪数据；迁移执行者不要直接读取包含目标案例的整个研究目录。

## 输入清单

明确提供：task_mode（reconstruction或transfer）、target_id、具体问题、材料截止时间及精度、新闻材料、模型名称与可用配置、父框架、候选操作、截止日前的分析师状态。记录所有输入文件哈希、提示全文、上下文来源和缺失材料。

还原模式另提供目标字幕，可提供已获确认的用户修订。迁移模式禁止提供目标字幕、目标期重建、目标期对照、作者后续结果及目标期或以后状态。只给经过裁剪的候选规则正文，不展开候选包中的案例证据链接。对于目标早于或等于475的任务，须标DEVELOPMENT_REPLAY，不能声称未见检验。

历史状态只是作者的信念。记录来源期数和发布时间，严格早于目标截止；同日先后不明则排除或标为时序不明输入，结果不作干净时序评价。仅有“以前说过”的回顾不能补造首发记录。

## 执行提示

你的任务是忠实表示该作者怎样形成观点。请按以下步骤工作：

1. 列本次材料范围、缺失输入与可使用的历史状态。事实内容、新闻中的他人观点、作者历史判断分开。
2. 选出关键线索并说明选择依据：角色关系、异常行为、时机、目标与现有手段、内部执行、预期渠道。只激活相关操作，不机械填满每条规则。
3. 提出核心问题。还原模式以作者实际追问为准；迁移模式标为框架推演，不能伪装成作者原话。
4. 写出前提到中间机制再到结论的链条。每个节点注明explicit、author_implied或assistant_reconstruction；前提缺失时保留缺口。未知资金渠道等不得补造。
5. 说明解释排序。明确作者或候选推演认为哪个目标、矛盾或约束更重要，提供依据。无依据则排序未知，不能默认“国内永远优先”。
6. 表达主倾向、原始确信措辞、范围和例外。还原模式原强度不得被系统审慎原则改写；迁移模式预测的强度不得冒称作者确信。猜测与强断言按命题分开，不赋予虚构数值概率。
7. 写出更新条件及预计改变方向。原文未给更新规则则标未表达，助手建议另列，不补写为作者方法。
8. 最后单列系统核验状态与竞争解释。它们用于说明证据地位，不替换作者层的结论。

## 输出结构

先输出可读分析，再输出结构化记录：task_mode、target_id、cutoff、input_manifest、active_operations、units、missing_inputs、system_verification。

每个unit包含：id、attention、question、premises、reasoning_steps、ranking、conclusion、author_force_quote、force_label、scope、conditions、update_rule、attribution、evidence_refs、reconstruction_gaps。迁移时author_force_quote为null，另填predicted_force与basis；原文缺少强度表达时不要杜撰引语。每条reasoning_step分别标归属和证据。

封存完整输入、模型/提示配置、原始输出与时间后才允许打开目标字幕。不要根据目标回写封存答案。若前置输入不全，可输出受限分析，但明确哪些维度无法公平比较。
