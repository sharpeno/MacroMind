# 新内容提取的九项语义自检

适用位置：原文阅读 → 初稿提取 → 本流程 → 人工复核或待审 → 固定规则版本更新 → 受控编译。不能用检查表自动批准新文字。

先冻结原提取、原文及其哈希。不得在看到判定后回头替换基线。

每条主张检查九项，并填原文cue编号和具体说明：

1. speaker_role：谁在说？博主本人、他人观点、假想讲话，还是助手解释？
2. modality：原话是断言、猜测、条件设想还是反问？不因事实未验证就擅自削弱原话强度；用作者归属区分真实性。
3. conditions：哪些“如果／只有／在……情况下”决定结论？不把局部条件无依据扩大为全部流程必备。
4. time_scope：事件阶段、时点、期限；不把预期或假想讲话写成已经发生。
5. objects：结论针对哪些人、市场、事物？保持同一对象，不擅自泛化。
6. assumptions：原因解释依赖哪些假设？例如所谓官方测算，可能只是博主假定的决策依据。
7. reasoning_relation：是在描述、并列列举、类比、解释原因、给出动机，还是推导？局部理由只支持对应结论。
8. alternatives：是否保留并列分支、反例或作者反对的观点？
9. external_evidence：原文有没有实际提供外部证据？没有时明确缺口，不能补造引用。

每项选择addressed（已说明）、not_in_excerpt（本段未提供）、unresolved（尚有疑问）。addressed必须绑定证据；not_in_excerpt不等于现实中不存在。缺项不得默认通过。

最后选择retain、revise或hold，写出候选文本及用途。原文完整并不意味着摘要必须逐句复制；没有足够理由时避免为了“更详细”而强迫修改。注意holdout001的EP004/C08：用户保留了摘要，不应把助手对细节的偏好写成硬性规则。

使用macromind.quality.semantic_review.validate_packet检查记录完整性与输入指纹。返回READY_FOR_HUMAN_REVIEW仅意味着自检材料可审核，永远不会产生semantic_acceptance或compile_authorization。它不调用模型，不独立判断自然语言忠实度。本次由助手按流程完成实际语义判断。

人工确认后，才按明确意见形成新注释并更新固定规则；继续使用compile_reviewed_episode.py，不能以自检通过绕过既有门禁。
